# Project instructions

This repository produces vertical motion-explainer videos (YouTube Shorts) with Remotion. Rules: `MASTER_PROMPT_FINAL.md` (v2.7, the single source of rules; do not change it unless the user asks; changes go to `docs/CHANGELOG.md`).

## Topics: one folder per topic
- Finished / current topic «Почему нам кажется, что время течёт быстро» lives in the root layout (`content/`, `public/audio/`, `src/scenes/`). Its state: `content/progress.md`, `content/decisions.md`.
- **A new topic** (the user writes «Новая тема: …», «Выполни MASTER_PROMPT_FINAL.md. Тема: …» or similar) never continues the root `content/progress.md`. Create it with `node scripts/new-topic.mjs <slug> "<Тема>"`, which makes:
  - `projects/<slug>/content/` — brief, sources, analysis, script, storyboard, sound map, reviews, `progress.md`, `decisions.md`;
  - `public/<slug>/` — voice files, sfx copies, fonts if new (Remotion serves static files only from `public/`);
  - `src/projects/<slug>/` — scenes, Main and Cover for this topic, registered in `src/Root.tsx` under composition ids `<Slug>Main` and `<Slug>Cover`;
  - `scripts/` and shared code (`src/lib`, `src/theme`, `src/components` incl. `Episode`, `src/illustrations`) are reused; extend them, do not copy them. Scripts take `--content`, `--timeline`, `--comp` flags for a topic (MASTER_PROMPT_FINAL §21).
- **Continuing** a topic: read that topic's `progress.md` and `decisions.md` first and continue from the recorded step; do not re-ask recorded decisions.
- Each topic gets its own working branch and PR.

## Always
- House style for every new topic: Anatomy toned solids in our palette (MASTER_PROMPT_FINAL §22): draw with `src/lib/anatomy.tsx` (AnatomyStage, anatomyProjection, Kit, paint) and `src/lib/physics.ts`; the old line-art kits are only for the finished «время» topic. Reference look: composition `AnatomyStyle`. Detail norm is maximal (§22.2): hero object 80–150 parts, every secondary object ≥ 40, environment ≥ 15 parts and ≤ 40% of that file's hero (a warning, not an error); parts list (PARTS) before geometry. `Assembly`'s `detail` flag (`complex` / `simple` / `schematic`) records how the object is read and does not lower that count. Reader's guide, no extra rules (§22 wins on conflict): `styles/anatomy/STYLE.md`.
- Any subject in the house style (§24): states of people by symbols from `src/lib/symbols/catalog.json` (mode `symbol` with cause, appearsOn, leavesOn); data, scale, documents, map, chronicle, nature, crowd, interfaces, money from `src/lib/primitives/`, `scale.tsx`, `nature.ts`, `crowd.ts`, `device.ts`, `money.ts`; materials `src/theme/materials.ts`; transitions `src/lib/transitions.ts`. Topic code never draws kit solids past `Assembly` (the audit refuses it). Shape-changing objects export `stateSweep` (object-audit checks every state); particles and sparks are `Dyn` parts passed as `extra`; every kit export is called in the showcase `AnatomyUniversal` (regress-checks), and `scripts/style-check.mjs` (CI) compares it with `styles/anatomy/refs`. `Assembly.lint()` runs first in `object-audit`; a new root cause adds a lint rule and a fixture in `scripts/fixtures/lint-broken.parts.ts`.
- Pace (§19.3, addendum 4.1): 1.5–3 s between visual events is a guide. A documented meaningful hold is allowed; a dead stretch is still a defect. A leading metaphor needs `metaphor-prep.md` and a later schematic scene; interfaces stay literal (§20).
- Motion (any topic): a scene or reel whose parts move is a pure state per frame in `src/projects/<slug>/*.motion.ts` exporting `MOTION` (`src/lib/motion.ts`: `beatClock`, `settle`, `blendCam`; a part that turns is rebuilt at its angle, never cross-faded). Moving parts are `dynTube` / `dynBall` / `dynSolid` with shapes: `src/lib/depth.ts` orders them against the static object by ray tests every frame. Frame with `camFit` (hero corners + pinned labels inside `safeRect`), not with zoom numbers. `node scripts/motion-check.mjs` (in audit, CI and pregate) walks every frame: depth cycles, parts through parts, arrows in the air, crop, empty half, jumps, jolts, pops, loop seam; `--video <mp4>` checks pixels, `--selftest` proves it on broken inputs. The audit refuses topic code that animates the old way (`camOn` / `camOnBox` / `lerpCam`, or a `.tsx` that animates house-style objects without a `*.motion.ts`); `new-topic.mjs` creates `scenes.motion.ts`; `master.mjs` fails on motion defects of the delivered file. Fading moving parts: `Assembly.svgFaded`, meaning changes: `handOver`.
- §25 (v2.8): concept.md carries three candidate structures; `distinct.json` (4 of 6 axes differ from the last topic); every plate with text stays ≥ max(1.5 s, chars ÷ 13 + 1.2 s) (`PlateProbe.text`, motion-check `read`); after the voice run `node scripts/transcribe.mjs --content … --public-prefix …` and `node scripts/vo-check.mjs --content …` (audit step `voice`); anatomy-plate techniques live in `src/lib/techniques.ts` (dye front, world-space hatching, explode / pull out).
- `node scripts/check-text.mjs` exits non-zero on caption defects. `audit.mjs` passes the selected `--timeline` to it as an argv array. Phone-size check of an exported master: `node scripts/review-video.mjs <master.mp4> <reviews-dir>` (360×640, SHA-256, near-black and empty frames, notes in that directory's `notes.json`).
- Hero objects: dossier by `object-researcher`, parts and motion plan by `object-architect` before STOP 1; build objects with `src/lib/assembly.ts` in `*.parts.ts` and run `node scripts/object-audit.mjs --settle` after any geometry change (zero problems before going on). Characters: `src/lib/rig.ts` + `src/lib/character.ts` (walkTo, reach/reachShare, holdInFront, sit); `scripts/rig-check.mjs` must pass. Labels and data: `src/components/Frontal.tsx`.
- Covers (§19.5): three variants in `src/projects/<slug>/covers.ts` on `AnatomyCover`; `node scripts/cover-check.mjs`; the hook is in the picture; record the user's choice in `projects/<slug>/content/cover.json`.
- Metaphors only for accuracy (MASTER_PROMPT_FINAL §20): every scene has a mode and location in `visual-register.json`; every metaphor is justified, checked by `metaphor-auditor` and approved by the user at STOP 1. Interfaces, schemes and data are shown literally. Avoid the typical errors of §20.5 (picture contradicts the voice, wrong unit, one image two meanings, decor that looks like data, hypothesis stated as fact); the storyboard has a «voice | frame» column per scene.
- Before the gate and before committing visual work, run `node scripts/audit.mjs` (no rendering) and fix every ERROR. Slow geometry checks (object-audit, rig-check) are cached by input hash, so a repeat run takes seconds.
- **Pre-gate first**: `node scripts/pregate.mjs <slug>` (types, lint, handedness, audit, covers, and `still-check` of the topic's style frames from `projects/<slug>/content/stills.json`). The quality-gate agents see frames only when pregate is green; a gate round that repeats a pregate finding is wasted. **Batch gate (§15):** machine checks run after every change; the `shorts-quality-gate` agent runs once per stop on the WHOLE set (STOP 2: all style frames and test reels of the topic; STOP 3: the full draft) or before any showing to the user, not per scene. Fix every defect of a round in one batch (root cause + guard each), rerun all machine checks on the whole set, then one re-gate. At most 2 gate rounds per set, the 3rd open item is escalated to the user (§15).
- **Handedness**: the kit's projection is LEFT-handed. Right-hand rules (force on a current I·L×B, torque, a field of a current) are computed with `physCross` / `forceOnWire` from `src/lib/handed.ts`, never with a plain cross product on kit vectors; `node scripts/handed-check.mjs` guards it.
- Parts files apply their own settled paint order (`X.applyKeys(KEYS.X)` inside `*.parts.ts`); after changing static parts run `node scripts/object-audit.mjs --settle <file>`. Cameras for frames use box corners (`boxCorners`), not three points.
- One coral part per frame with ONE meaning per topic (`coralMeaning` and per-scene `coral` in `visual-register.json`); every script scene cites claim ids that exist in `dossier.json`.
- Never run `prettier --write` on a file you are still editing (it changes the file under you and the next edit fails); hand-written code is listed in `.prettierignore`, eslint is the style gate. Moving parts (turning loops, wheels) export `dynamicShapes(theta)` from their `*.parts.ts`: `object-audit` sweeps them through a half turn against the static solids.
- Subagents may not be able to write files or open some sites: they return the full report as text, the main session saves it.
- For the gate, make 2 fps sheets and beat key frames with `node scripts/contact-sheet.mjs <outDir>`, and per-frame strips with `node scripts/frame-strip.mjs <from> <to>` for physics and anchors (stills only, no video render). Keep review notes in `content/reviews/notes.json` (id, severity, status); escalate a note open for 3 rounds to the user.
- After changing a scene, re-check its sfx and run `node scripts/audit.mjs --stamp-sfx`.
- Master: `node scripts/master.mjs` (render, loudness on the encoded AAC, format checks, cover, report).
- **Context hand-over**: keep the current step, open findings and next actions in `docs/progress/<work>.md` (committed with the work). At 40% context use (read the session's context counter, never estimate: the window can be 1M tokens, so 40% is 400k), save that file, open a PR and merge it on green CI. The user works in ONE session: never start a new session (`create_session`) for a hand-over; the next session (or this one after compaction) continues from `docs/progress/<work>.md`.
- **Root cause every time** (`docs/root-causes.md`): no defect is closed by a fix in one topic alone. Name the root cause (what in the shared code or process let it through), fix it in shared code or the `new-topic.mjs` template, and add a guard: an automatic check, with a `--selftest` case on a deliberately broken input where possible. A `fixed` / `verified` note in `reviews/notes.json` carries `rootCause` and `guard` (an existing `scripts/…` or `src/…` path); the audit enforces it. Add a row to `docs/root-causes.md` in the same PR. When a gate agent finds a defect a machine check missed, extending that check is part of the fix.
- Before showing frames, covers or video to the user, run the `shorts-quality-gate` agent (§19) and fix every defect it finds; facts go through `fact-checker`. After a PASS, stamp the exact files: `node scripts/gate-stamp.mjs --gate "<verdict>" <files>`; the PreToolUse hook `.claude/hooks/require-gate.mjs` blocks sending an unstamped image or video.
- Never merge a PR that adds or changes a video (a render, a demo or a master) until the session merging it has watched the new video itself (contact sheets and `node scripts/review-video.mjs`); green CI alone is not enough. A PR without a video is merged on green CI.
- Do not reuse illustrations or locations from another topic without the user's consent (§4); shared kits (room, city, board) are building blocks, the scenes are designed anew.
- Code map: for questions about how the code is wired or what a change in shared code (`src/lib`, `src/components`, `src/theme`) affects, use the `graph-pilot` skill (Graphify, installed by the SessionStart hook; `graphify update .` builds the graph in seconds, only code-only commands, never `graphify install`).
- The user works from a phone: answer in Russian, keep messages short, send images and videos as files.
