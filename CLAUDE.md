# Project instructions

This repository produces vertical motion-explainer videos (YouTube Shorts) with Remotion. Rules: `MASTER_PROMPT_FINAL.md` (v2.5, the single source of rules; do not change it unless the user asks; changes go to `docs/CHANGELOG.md`).

## Topics: one folder per topic
- There is no root topic. Every topic lives under `projects/<slug>/`.
- **A new topic** (the user writes «Новая тема: …», «Выполни MASTER_PROMPT_FINAL.md. Тема: …» or similar) is created with `node scripts/new-topic.mjs <slug> "<Тема>"`, which makes:
  - `projects/<slug>/content/` — brief, sources, analysis, script, storyboard, sound map, reviews, `progress.md`, `decisions.md`;
  - `public/<slug>/` — voice files, sfx copies, fonts if new (Remotion serves static files only from `public/`);
  - `src/projects/<slug>/` — scenes, Main and Cover for this topic, registered in `src/Root.tsx` under composition ids `<Slug>Main` and `<Slug>Cover`;
  - `scripts/` and shared code (`src/lib`, `src/theme`, `src/components` incl. `Episode`) are reused; extend them, do not copy them. Scripts take `--content`, `--timeline`, `--comp` flags for a topic (MASTER_PROMPT_FINAL §21).
- **Continuing** a topic: read `projects/<slug>/content/progress.md` and `decisions.md` first and continue from the recorded step; do not re-ask recorded decisions.
- Each topic gets its own working branch and PR.

## Always
- House style for every topic: Anatomy toned solids in our palette (MASTER_PROMPT_FINAL §22): draw with `src/lib/anatomy.tsx` (AnatomyStage, anatomyProjection, Kit, paint) and `src/lib/physics.ts`. Contour Line Art stays documented in MASTER_PROMPT_FINAL §4 and is not used by any topic in this repository. Reference look: composition `AnatomyStyle`. Detail norm is maximal (§22.2): hero object 80–150 parts, every secondary object ≥ 40, environment ≥ 15 parts and ≤ 40% of that file's hero (a warning, not an error); parts list (PARTS) before geometry. `Assembly`'s `detail` flag (`complex` / `simple` / `schematic`) records how the object is read and does not lower that count. Reader's guide, no extra rules (§22 wins on conflict): `styles/anatomy/STYLE.md`.
- Pace (§19.3, addendum 4.1): 1.5–3 s between visual events is a guide. A documented meaningful hold is allowed; a dead stretch is still a defect. A leading metaphor needs `metaphor-prep.md` and a later schematic scene; interfaces stay literal (§20).
- `node scripts/check-text.mjs --timeline <timeline.json>` exits non-zero on caption defects. `audit.mjs` passes the selected `--timeline` to it as an argv array. Phone-size check of an exported master: `node scripts/review-video.mjs <master.mp4> <reviews-dir>` (360×640, SHA-256, near-black and empty frames, notes in that directory's `notes.json`).
- Hero objects: dossier by `object-researcher`, parts and motion plan by `object-architect` before STOP 1; build objects with `src/lib/assembly.ts` in `*.parts.ts` and run `node scripts/object-audit.mjs --settle` after any geometry change (zero problems before going on). Characters: `src/lib/rig.ts` + `src/lib/character.ts` (walkTo, reach/reachShare, holdInFront, sit); `scripts/rig-check.mjs` must pass. Labels and data: `src/components/Frontal.tsx`.
- Covers (§19.5): three variants in `src/projects/<slug>/covers.ts` on `AnatomyCover`; `node scripts/cover-check.mjs`; the hook is in the picture; record the user's choice in `projects/<slug>/content/cover.json`.
- Metaphors only for accuracy (MASTER_PROMPT_FINAL §20): every scene has a mode and location in `visual-register.json`; every metaphor is justified, checked by `metaphor-auditor` and approved by the user at STOP 1. Interfaces, schemes and data are shown literally. Avoid the typical errors of §20.5 (picture contradicts the voice, wrong unit, one image two meanings, decor that looks like data, hypothesis stated as fact); the storyboard has a «voice | frame» column per scene.
- Before the gate and before committing visual work, run `node scripts/audit.mjs --scenes src/projects/<slug>/scenes --content projects/<slug>/content --timeline src/projects/<slug>/data/timeline.json` (no rendering) and fix every ERROR. A run without flags checks the shared core only. Slow geometry checks (object-audit, rig-check) are cached by input hash, so a repeat run takes seconds.
- **Pre-gate first**: `node scripts/pregate.mjs <slug>` (types, lint, handedness, audit, covers, and `still-check` of the topic's style frames from `projects/<slug>/content/stills.json`). The quality-gate agents see frames only when pregate is green; a gate round that repeats a pregate finding is wasted. At most 2 gate rounds per set of frames, the 3rd open item is escalated to the user (§15).
- **Handedness**: the kit's projection is LEFT-handed. Right-hand rules (force on a current I·L×B, torque, a field of a current) are computed with `physCross` / `forceOnWire` from `src/lib/handed.ts`, never with a plain cross product on kit vectors; `node scripts/handed-check.mjs` guards it.
- Parts files apply their own settled paint order (`X.applyKeys(KEYS.X)` inside `*.parts.ts`); after changing static parts run `node scripts/object-audit.mjs --settle <file>`. Cameras for frames use box corners (`boxCorners`), not three points.
- One coral part per frame with ONE meaning per topic (`coralMeaning` and per-scene `coral` in `visual-register.json`); every script scene cites claim ids that exist in `dossier.json`.
- Never run `prettier --write` on a file you are still editing (it changes the file under you and the next edit fails); hand-written code is listed in `.prettierignore`, eslint is the style gate. Moving parts (turning loops, wheels) export `dynamicShapes(theta)` from their `*.parts.ts`: `object-audit` sweeps them through a half turn against the static solids.
- Subagents may not be able to write files or open some sites: they return the full report as text, the main session saves it.
- For the gate, make 2 fps sheets and beat key frames with `node scripts/contact-sheet.mjs <outDir> --comp <Slug>Main --timeline src/projects/<slug>/data/timeline.json`, and per-frame strips with `node scripts/frame-strip.mjs <from> <to> --comp <Slug>Main` for physics and anchors (stills only, no video render). Keep review notes in `projects/<slug>/content/reviews/notes.json` (id, severity, status); escalate a note open for 3 rounds to the user.
- After changing a scene, re-check its sfx and run `node scripts/audit.mjs --stamp-sfx --scenes src/projects/<slug>/scenes --content projects/<slug>/content --timeline src/projects/<slug>/data/timeline.json`.
- Master: `node scripts/master.mjs --comp <Slug>Main --timeline src/projects/<slug>/data/timeline.json --out out/<slug>` (render, loudness on the encoded AAC, format checks, cover, report).
- Before showing frames, covers or video to the user, run the `shorts-quality-gate` agent (§19) and fix every defect it finds; facts go through `fact-checker`.
- Do not reuse illustrations or locations from another topic without the user's consent (§4); scenes are designed anew.
- Code map: for questions about how the code is wired or what a change in shared code (`src/lib`, `src/components`, `src/theme`) affects, use the `graph-pilot` skill (Graphify, installed by the SessionStart hook; `graphify update .` builds the graph in seconds, only code-only commands, never `graphify install`).
- The user works from a phone: answer in Russian, keep messages short, send images and videos as files.
