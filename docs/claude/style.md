# House style, objects and metaphors (moved verbatim from CLAUDE.md)

Rules here bind as if written in CLAUDE.md; the rules themselves: `docs/rules/INDEX.md` (generated from `MASTER_PROMPT_FINAL.md`).

- House style for every new topic: Anatomy toned solids in our palette (MASTER_PROMPT_FINAL §22): draw with `src/lib/anatomy.tsx` (AnatomyStage, anatomyProjection, Kit, paint) and `src/lib/physics.ts`; the old line-art kits are only for the finished «время» topic. Reference look: composition `AnatomyStyle`. Detail norm is maximal (§22.2): hero object 80–150 parts, every secondary object ≥ 40, environment ≥ 15 parts and ≤ 40% of that file's hero (a warning, not an error); parts list (PARTS) before geometry. `Assembly`'s `detail` flag (`complex` / `simple` / `schematic`) records how the object is read and does not lower that count. Reader's guide, no extra rules (§22 wins on conflict): `styles/anatomy/STYLE.md`.
- Any subject in the house style (§24): states of people by symbols from `src/lib/symbols/catalog.json` (mode `symbol` with cause, appearsOn, leavesOn); data, scale, documents, map, chronicle, nature, crowd, interfaces, money from `src/lib/primitives/`, `scale.tsx`, `nature.ts`, `crowd.ts`, `device.ts`, `money.ts`; materials `src/theme/materials.ts`; transitions `src/lib/transitions.ts`. Topic code never draws kit solids past `Assembly` (the audit refuses it). Shape-changing objects export `stateSweep` (object-audit checks every state); particles and sparks are `Dyn` parts passed as `extra`; every kit export is called in the showcase `AnatomyUniversal` (regress-checks), and `scripts/style-check.mjs` (CI) compares it with `styles/anatomy/refs`. `Assembly.lint()` runs first in `object-audit`; a new root cause adds a lint rule and a fixture in `scripts/fixtures/lint-broken.parts.ts`.
- Hero objects: dossier by `object-researcher`, parts and motion plan by `object-architect` before STOP 1; build objects with `src/lib/assembly.ts` in `*.parts.ts` and run `node scripts/object-audit.mjs --settle` after any geometry change (zero problems before going on). Characters: `src/lib/rig.ts` + `src/lib/character.ts` (walkTo, reach/reachShare, holdInFront, sit); `scripts/rig-check.mjs` must pass. Labels and data: `src/components/Frontal.tsx`.
- Covers (§19.5): three variants in `src/projects/<slug>/covers.ts` on `AnatomyCover`; `node scripts/cover-check.mjs`; the hook is in the picture; record the user's choice in `projects/<slug>/content/cover.json`.
- Metaphors only for accuracy (MASTER_PROMPT_FINAL §20): every scene has a mode and location in `visual-register.json`; every metaphor is justified, checked by `metaphor-auditor` and approved by the user at STOP 1. Interfaces, schemes and data are shown literally. Avoid the typical errors of §20.5 (picture contradicts the voice, wrong unit, one image two meanings, decor that looks like data, hypothesis stated as fact); the storyboard has a «voice | frame» column per scene.
- **Handedness**: the kit's projection is LEFT-handed. Right-hand rules (force on a current I·L×B, torque, a field of a current) are computed with `physCross` / `forceOnWire` from `src/lib/handed.ts`, never with a plain cross product on kit vectors; `node scripts/handed-check.mjs` guards it.
- Parts files apply their own settled paint order (`X.applyKeys(KEYS.X)` inside `*.parts.ts`); after changing static parts run `node scripts/object-audit.mjs --settle <file>`. Cameras for frames use box corners (`boxCorners`), not three points.
- One coral part per frame with ONE meaning per topic (`coralMeaning` and per-scene `coral` in `visual-register.json`); every script scene cites claim ids that exist in `dossier.json`.
- Never run `prettier --write` on a file you are still editing (it changes the file under you and the next edit fails); hand-written code is listed in `.prettierignore`, eslint is the style gate. Moving parts (turning loops, wheels) export `dynamicShapes(theta)` from their `*.parts.ts`: `object-audit` sweeps them through a half turn against the static solids.
