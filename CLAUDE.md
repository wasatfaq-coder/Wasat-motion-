# Project instructions

This repository produces vertical motion-explainer videos (YouTube Shorts) with Remotion. Rules: `MASTER_PROMPT_FINAL.md` (v2.6, the single source of rules; do not change it unless the user asks; changes go to `docs/CHANGELOG.md`).

## Topics: one folder per topic
- Finished / current topic «Почему нам кажется, что время течёт быстро» lives in the root layout (`content/`, `public/audio/`, `src/scenes/`). Its state: `content/progress.md`, `content/decisions.md`.
- **A new topic** (the user writes «Новая тема: …», «Выполни MASTER_PROMPT_FINAL.md. Тема: …» or similar) never continues the root `content/progress.md`. Create it with `node scripts/new-topic.mjs <slug> "<Тема>"`, which makes:
  - `projects/<slug>/content/` — brief, sources, analysis, script, storyboard, sound map, reviews, `progress.md`, `decisions.md`;
  - `public/<slug>/` — voice files, sfx copies, fonts if new (Remotion serves static files only from `public/`);
  - `src/projects/<slug>/` — scenes, Main and Cover for this topic, registered in `src/Root.tsx` under composition ids `<Slug>Main` and `<Slug>Cover`;
  - `scripts/` and shared code (`src/lib`, `src/theme`, `src/components` incl. `Episode`, `src/illustrations`) are reused; extend them, do not copy them. Scripts take `--content`, `--timeline`, `--comp` flags for a topic (MASTER_PROMPT_FINAL §21).
- **Continuing** a topic: read that topic's `progress.md` and `decisions.md` first and continue from the recorded step; do not re-ask recorded decisions.
- Each topic gets its own working branch and PR.

## Always
- House style for every new topic: Anatomy toned solids in our palette (MASTER_PROMPT_FINAL §22): draw with `src/lib/anatomy.tsx` (AnatomyStage, anatomyProjection, Kit, paint) and `src/lib/physics.ts`; the old line-art kits are only for the finished «время» topic. Reference look: composition `AnatomyStyle`. Detail norm is maximal (§22.2): hero object 80–150 parts, every secondary physical object ≥ 40, environment detailed too (no «simple» exemption; `detail: 'schematic'` only for scheme blocks, arrows and plates); parts list (PARTS) before geometry.
- Anatomy Shorts standard (MASTER_PROMPT_FINAL §23, the user's Grill Me decisions, highest priority for new topics): the mechanism works continuously and a new meaningful event lands every 1.5–3 s (`motion-plan.json`, `node scripts/motion-plan-check.mjs`); full causal walk-through of the main nodes; one coral semantic group; explanatory projections by purpose; three hooks in `hooks.json`; production order sketches → animatic → hardest fragment → full build. Statuses of the patch items 1–27: `docs/patch-status.md`.
- Hero objects: dossier by `object-researcher`, parts and motion plan by `object-architect` before STOP 1; build objects with `src/lib/assembly.ts` in `*.parts.ts` and run `node scripts/object-audit.mjs --settle` after any geometry change (zero problems before going on). Characters: `src/lib/rig.ts` + `src/lib/character.ts` (walkTo, reach/reachShare, holdInFront, sit); `scripts/rig-check.mjs` must pass. Labels and data: `src/components/Frontal.tsx`.
- Covers (§19.5): three variants in `src/projects/<slug>/covers.ts` on `AnatomyCover`; `node scripts/cover-check.mjs`; the hook is in the picture; record the user's choice in `projects/<slug>/content/cover.json`.
- Metaphors only for accuracy (MASTER_PROMPT_FINAL §20): every scene has a mode and location in `visual-register.json`; every metaphor is justified, checked by `metaphor-auditor` and approved by the user at STOP 1. A leading metaphor links to a precise schematic scene. Real interface actions are shown literally in a frontal close-up. Apply §22.5 to topic acceptance. Avoid the typical errors of §20.5 (picture contradicts the voice, wrong unit, one image two meanings, decor that looks like data, hypothesis stated as fact); the storyboard has a «voice | frame» column per scene.
- Before the gate and before committing visual work, run `node scripts/audit.mjs` (no rendering) and fix every ERROR.
- For the gate, make 2 fps sheets and beat key frames with `node scripts/contact-sheet.mjs <outDir>`, and per-frame strips with `node scripts/frame-strip.mjs <from> <to>` for physics and anchors (stills only, no video render). Keep review notes in `content/reviews/notes.json` (id, severity, status); escalate a note open for 3 rounds to the user.
- After changing a scene, re-check its sfx and run `node scripts/audit.mjs --stamp-sfx`.
- Master: `node scripts/master.mjs` renders a **candidate** (loudness on the encoded AAC, format checks, cover, input fingerprint, SHA-256); it is never a release. Record the review in `reviews/quality-gate.json` (all frames in blocks, playback with sound, notes; `node scripts/qa-gate.mjs <file>` validates it) and release only with `node scripts/release.mjs` (same bytes, fresh fingerprint, no open blockers; `fixed` still blocks). Regression tests: `npm test`.
- Before showing frames, covers or video to the user, run the `shorts-quality-gate` agent (§19) and fix every defect it finds; facts go through `fact-checker`.
- Do not reuse illustrations or locations from another topic without the user's consent (§4); shared kits (room, city, board) are building blocks, the scenes are designed anew.
- Code map: for questions about how the code is wired or what a change in shared code (`src/lib`, `src/components`, `src/theme`) affects, use the `graph-pilot` skill (Graphify, installed by the SessionStart hook; `graphify update .` builds the graph in seconds, only code-only commands, never `graphify install`).
- The user works from a phone: answer in Russian, keep messages short, send images and videos as files.
