# Интеграция Anatomy: аналитический рендер сложных объектов

Техническое описание, 13 ноября 2026 года. Статус: **стиль утверждён** (тонированные тела в нашей палитре, §22). Выполнено: П0 — ядро `iso-kit`, адаптер, физика `physics.ts`, образец `AnatomyStyle`. Дальше: П1–П4.

## 1. Задача и принятые решения

Нужен агентный механизм, который до рендера изучает тему и устройство объектов: интерфейсы, архитектуру, принцип работы, например чипа. Затем объекты рисуются достоверно и подробно в изометрии, с шейповой анимацией и правильной физикой движения предметов и персонажей.

Источник идей — скилл [Anatomy](https://github.com/wheresryan22/anatomy) (MIT, коммит `1482e84`).

Решения пользователя (интервью, вопросы 1–8):

| № | Вопрос | Решение |
| --- | --- | --- |
| 1 | Что взять из Anatomy | Геометрическое ядро и аудит перенести в Remotion; движение считается от номера кадра; перенять их процесс «правда → список деталей → проверка». Результат — видео Shorts |
| 2 | Метафора или устройство | Буквально и в разрезах: корпус → разрез → слои → деталь. Машина-метафора — только для невидимых идей, через реестр §20 |
| 3 | Источники для досье | Агент сам ищет первичные источники: даташиты, документацию, патенты, разборы, учебники. У каждой детали и цифры есть ссылка; всё без источника помечается как упрощение |
| 4 | Согласование | Досье и список деталей показываются на СТОП 1 вместе со сценарием; стайлфрейм узла — на СТОП 2 |
| 5 | Персонажи | Риг человека (скелет, суставы, ходьба, позы, взять и нажать) и крупная рука для работы с устройствами |
| 6 | Эффекты | Только SVG. Круглые детали вращаются честно, потоки (ток, данные, жидкость) — частицы по трассам. WebGL и 3D-режим Anatomy не берём |
| 7 | Движок | Одно ядро для новых тем; наборы комнаты и города переносятся на него постепенно, когда понадобятся. Ролик «время» не трогаем |
| 8 | Сейчас | Это описание; пилот — после одобрения |

## 2. Что такое Anatomy

Anatomy — Agent Skill для Claude Code. Он строит интерактивные изометрические фигуры для браузера: SVG, при желании WebGL и бета-3D. Фигура строится из 40–150 и более мелких твёрдых деталей с четырьмя тонами по направлению граней.

Что полезно для нас:
- **Ядро** `kit/iso-kit.ts`: камера, тела, выдавливание, цилиндры, накатка, пружины, линейки, тики, перенос вдоль осей.
- **Круглые детали** `kit/lathe.mjs`: тела вращения вокруг любой оси, с плавной тонировкой без «лесенки», рёбрами и кругами болтов.
- **Трубы и кабели** `kit/tube.mjs`: делятся на куски для сортировки по глубине, с хомутами и оплёткой.
- **Аудит** `kit/audit.mjs`: доказывает, что ничего ни через что не проходит, каждый конец сидит на креплении, нет складок и наложений и все перекрытия нарисованы в верном порядке глубины. Проверка идёт в покое, в разборе и в каждом кадре между ними.
- **Методика:** размер фигуры (Figure, Hero, Epic) со сроками; «сначала правда» — модель с реальными числами; список деталей до геометрии; порядок рисования сзади вперёд, доказанный, а не подобранный на глаз; проверка лупой на увеличении 4×; правило «каждая линия где-то заканчивается».

Что не подходит:
- **Движение по таймеру.** `requestAnimationFrame`, указатель и клавиатура запрещены в Remotion (§12) — заменяется расчётом позы от кадра.
- **Карточка с заголовком и показаниями.** Противоречит §19.1 — отключается.
- **Машина-метафора как главный принцип.** Противоречит §20 для устройств — берём только буквальный режим.
- **WebGL и 3D-бета** — решение 6.
- **Персонажи.** В Anatomy их нет, риг строим сами (раздел 6).

## 3. Совместимость

**Проекция совпадает точно.** У Anatomy `x' = (x·sinA − y·cosA)·k`, `y' = ((x·cosA + y·sinA)·sinE − z·cosE)·k`. Наша проекция (`src/lib/iso.ts`): `x' = cos30·(x − y)·s`, `y' = 0,5·(x + y)·s − z·s`. Они совпадают при:
- азимуте 45°;
- угле возвышения 35,264° (истинная изометрия, `sinE = tan30°`);
- `k = 1,2247·s`, то есть `scale = 0,9682·s`.

Поэтому новые детали встают в наши сцены без пересчёта. Пилот проверит совпадение пикселей.

**Чистота и детерминизм.** В `iso-kit`, `lathe`, `tube` и `audit` нет `document` и `window`, нет случайных чисел. Строки SVG строятся детерминированно. В `audit.mjs` `Date.now` используется только для журнала. Условия §12 выполняются.

**React.** `kit/react/draw.tsx` — серверные компоненты без состояния: `Solid`, `Line`, `Wire`, `Dots`. Они работают в Remotion как обычные SVG-компоненты. `live.tsx` (хуки с таймером) не переносится.

**Цвет.** Тона `lo`, `mid`, `hi`, `faint`, `lit` и четыре оттенка граней задаются через CSS-классы `ISO_CSS`. В адаптере они отображаются на наши токены: фон, контур `ink`, 2–3 нейтральных, один коралловый акцент — только у смысловой детали. Толщины линий берутся из `STROKE`.

## 4. Архитектура в нашем наборе

```text
src/vendor/anatomy/          копия ядра Anatomy (iso-kit.ts, lathe, tube, audit) + LICENSE MIT, коммит 1482e84
src/lib/anatomy.ts           адаптер: проекция = наша, тона = токены, Solid/Line/Wire/Dots в стиле набора
src/lib/physics.ts           физика от кадра: пружина (аналитическое решение), баллистика, отскок, запаздывание, контакт
src/lib/rig.ts               риг персонажа: кости, обратная кинематика ног и рук, цикл шага, позы, захват
src/objects/<object>/        объект как модуль:
  dossier.json               досье: состав, размеры, материалы, принцип работы, порядок действий, источники
  model.ts                   чистая модель: параметры и состояния как функции времени (что движется и почему)
  parts.ts                   геометрия, построенная один раз в покое (список деталей ≥ 40 для героя)
  pose.ts                    поза в кадре f: сдвиги, повороты, разбор/сборка, вращение круглых деталей
  Object.tsx                 компонент Remotion: части в доказанном порядке глубины
  audit.mjs                  аудит геометрии по позам на якорях и каждые N кадров
scripts/object-audit.mjs     запуск аудита всех объектов темы (в audit.mjs и CI)
```

**Как рисуется кадр.** Геометрия строится один раз, в покое: пути SVG считаются заранее. В кадре `f` модуль `pose.ts` вычисляет состояние модели, сдвиги и повороты групп деталей. Компонент применяет их через `transform`, а пересобирает только детали, у которых меняется форма: пружина, лента, гибкий кабель. Порядок глубины берётся из `settle` аудита для каждого набора поз; при разборе он сортируется по ключам.

**Шейповая анимация.** Используются:
- разборка и сборка по группам с затухающими пружинами;
- раскрытие разреза: слой за слоем, крышка уходит по оси;
- прорисовка контура вдоль пути;
- морфинг форм с одинаковым числом точек (как `spot-plate` у Anatomy);
- рост трасс и частицы по кабелям.

**Вращение круглых деталей.** Шестерни, вентиляторы и диски строятся `lathe`. Вращение — это сдвиг угла зубьев, лопастей и рёбер вокруг оси с той же тонировкой. Поворачивать картинку целиком запрещено: в изометрии это неверно.

**Потоки.** Ток, данные, жидкость — точки, идущие по трассе `tube` с постоянной скоростью из модели. Их число и скорость берутся из досье, а не из головы.

## 5. Физика движения (src/lib/physics.ts)

Всё считается от времени `t = f / fps`, без накопления состояния между кадрами (§12):

- **Пружина.** Аналитическое решение затухающего осциллятора: недодемпфированный и критический режимы, жёсткость и демпфирование из модели. Поэтому перерегулирование и затухание реальные.
- **Полёт.** Подготовка (небольшое движение назад), баллистика `z = z0 + v·t − g·t²/2` с вращением, приземление со сплющиванием и отскоками с коэффициентом восстановления, затем покой.
- **Запаздывание.** Мелкие части (кабель, антенна, лист) следуют за носителем с задержкой и пружиной.
- **Контакт.** Предмет лежит на поверхности: высота опоры берётся из геометрии, а не задаётся числом. Тень зависит от высоты над опорой.
- **Скорости из досье.** Время закрытия клапана, частота вращения, ход поршня. В видео допускается масштаб времени, но он записывается в модель и не выдаётся за реальную скорость.

## 6. Риг персонажей (src/lib/rig.ts)

- **Скелет:** таз, позвоночник, голова, плечо, предплечье, кисть, бедро, голень, стопа. Части тела — твёрдые детали ядра (капсулы, бруски) в стиле набора.
- **Ходьба:** цикл шага с фазами опоры и переноса. Стопа в опоре прибита к полу (без скольжения), таз качается по высоте. Шаг и темп берутся из скорости персонажа.
- **Руки:** обратная кинематика по двум костям к цели (кнопка, ручка, деталь). Пальцы задаются позами: открыта, щепоть, нажим, хват. Контакт пальца с кнопкой проверяется аудитом: без зазора и без провала.
- **Крупная рука:** отдельный объект из 15–25 деталей для сцен «вставить», «нажать», «повернуть».
- **Позы:** стоять, сидеть, наклониться, нести; переходы с упреждением и доводкой.

## 7. Агентный механизм до рендера

Порядок для темы со сложными объектами. Существующие этапы §8 сохраняются, новые помечены ★.

1. **topic-analyst.** Главная мысль, шаги, утверждения с источниками.
2. ★ **object-researcher** (новый агент). Для каждого героя (чип, двигатель, интерфейс) ищет первичные источники и пишет `dossier.json`:
   - состав по узлам;
   - размеры и пропорции;
   - материалы;
   - принцип работы шагами;
   - порядок движений и их скорости;
   - что видно снаружи, в разрезе и в увеличении;
   - ссылка у каждой записи; всё без источника идёт с пометкой `simplified` и причиной.
3. ★ **object-architect** (новый агент). По досье и сценарию пишет:
   - список деталей: не меньше 40 для объекта и 80–150 для героя; группы основание → конструкция → механизм → объект показа; каждая деталь на что-то опирается;
   - план мира: единицы, раскладка, камера;
   - план разрезов: какие слои снимаются на каких словах;
   - сценарий движения по якорям: что движется, физика, параметры;
   - размер по шкале Anatomy с оценкой времени. Epic не начинается без решения пользователя.
4. **metaphor-auditor** (§20) и **fact-checker.** Режим «буквально» соблюдён; досье соответствует источникам; метафоры только для невидимого.
5. **СТОП 1.** Пользователю показываются сценарий, раскадровка, досье и список деталей.
6. **Сборка.** Геометрия, модель и поза делаются ядром; затем стайлфрейм узла.
7. ★ **object-audit.** Аудит ядра по позам: каждый якорь, каждые N кадров движения, разбор и сборка. Проверяются:
   - зазоры;
   - опоры и концы;
   - складки труб;
   - порядок глубины;
   - касания пальцев и стоп.

   Работа продолжается только при нуле ошибок. Аудит входит в `scripts/audit.mjs` и CI.
8. ★ **Проверка лупой.** `contact-sheet` строит ключевые кадры в полном размере и врезки 4× по узлам из списка деталей. **art-director** проверяет:
   - каждая линия на чём-то заканчивается;
   - на увеличении нет голых граней;
   - тонировка без «лесенки».
9. **СТОП 2.** Стайлфрейм узла и тестовый фрагмент.
10. Дальше без изменений: аниматик, полный черновик, **shorts-quality-gate**, **motion-critic** по покадровым лентам (физика), мастер.

**Контракты данных.**
- `dossier.json`: `{object, sources[], parts[{id, name, group, size, material, source|simplified}], principle[{step, what, moves, speed, source}], views{outside, cutaway[], closeup[]}}`.
- `parts.ts` экспортирует `PARTS` с `id` из досье. Проверка не даёт нарисовать деталь, которой нет в досье, и наоборот: каждая деталь досье либо нарисована, либо явно исключена.
- `model.ts` экспортирует `stateAt(t)`. Числа в кадре и в голосе берутся только из модели.

## 10. Риски и ограничения

- **Сроки Anatomy велики:** Hero — 2–4 часа на один объект. Сложная тема в 60–120 с с несколькими героями — это дни. Тему сужаем или делим на серию (§7).
- **Аудит рассчитан на разбор и покой.** Для длинного движения проверяем выборку поз; полная проверка каждого кадра долгая и идёт в фоне.
- **Стиль Anatomy — тонированные тела** с четырьмя оттенками, наш — контурный Line Art. Адаптер должен выровнять их; пилот покажет, нужен ли компромисс (например, 2 тона вместо 4).
- **Качество досье зависит от открытых источников.** Внутреннее устройство закрытых чипов известно частично. Такие места помечаются как упрощение и не выдаются за точную схему.
- **Персонажи — собственная разработка** без готовой основы в Anatomy, это самый рискованный этап (П3).
- **Лицензия MIT** требует сохранить уведомление об авторстве: файл LICENSE в `src/vendor/anatomy/`.
- **Новые агенты** доступны в сессии только после перезапуска; до этого их роль выполняет универсальный агент по тому же тексту, и это честно указывается.
