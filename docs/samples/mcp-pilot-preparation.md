# Подготовка новой метафоры для MCP

**Статус** — предложено. Досье и план ниже подготовлены для эскизирования и СТОП 1.

Главная мысль для пересказа: приложение через своего MCP-клиента вызывает инструмент на сервере и получает результат. Фрагмент показывает один успешный вызов инструмента через существующее подключение. Источник — [раздел Tool Execution спецификации архитектуры MCP](https://modelcontextprotocol.io/docs/learn/architecture#understanding-the-tool-execution-request).

| Образ | Сильная сторона | Риск |
| --- | --- | --- |
| Копицентр с окошком приёма и копиром | Лист, входной лоток и выходной лоток дают узнаваемый цикл «отправили, обработали, получили» | Может показаться, что любая задача MCP — печать или копирование |
| Мастерская с приёмным окном и верстаком | Заявка и выдача узнаваемы, можно показать работу инструмента | Без конкретного предмета верстак снова может выглядеть как неизвестное устройство |
| Точная схема | Явно показывает хост, вложенного клиента и сервер | Требует сразу прочитать три технические роли |

**Предложение для эскиза — копицентр.** Опознавательные детали: стойка приёма с листом, копир с крышкой, входной лоток с бумагой и выходной лоток с готовым листом. Досье физического героя следует дополнить референсом конкретного копира перед планом деталей. Метафора опирается на привычное действие с листом и лотками.

| Кадр | Действие | Что означает |
| --- | --- | --- |
| 0–2,5 с, общий план | Лист с задачей выходит из окна приёма и движется к копиру | Окно внутри помещения — MCP-клиент внутри приложения. Лист — вызов инструмента |
| 2,5–5 с, крупный план | Копир принимает лист. Из выходного лотка выходит лист с видимым результатом и движется к окну | Сервер исполняет инструмент и возвращает результат. Обратный путь виден до появления схемы |
| 5–9 с, схема | Положения отправителя и получателя сохраняются. На их местах раскрываются подписи и стрелки запроса и результата | Хост содержит MCP-клиент, клиент связывается с сервером. Схема уточняет границы аналогии |

Метка «Условный пример» вводит образ. В озвучке «Клиент отправляет вызов. Сервер выполняет инструмент и возвращает результат». MCP не изображается отдельной машиной, а обозначает связь по протоколу. Для эскиза акцент переходит с вызова на результат.

До геометрии проверить силуэты и действие на трёх эскизах 360×640. Рецензент сначала называет увиденное без объяснения. Если он не распознаёт окно, копир или возврат результата, исправить эскиз и повторить проверку. После согласования — план деталей и опор, аниматик и рендер. После рендера — независимая перепроверка исправленных мест и зрительский пересказ.
